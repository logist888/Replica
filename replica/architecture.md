## Что дало чтение публичных документов EF

Прочитан текст Academic and Technical Development Report (извлечён из PDF) и два отчёта по корреляции. Прочитаны не все разделы; приведены только факты, которые видел.

Известно (из отчёта):
- Доставка: computer-adaptive multi-stage testing (ca-MST). Три стадии: модуль 1 (середина B1), затем один из трёх модулей стадии 2 (середины A2, B1, B2), затем один из четырёх модулей стадии 3 (на границах уровней). Маршрутизация по порогам суммарного балла, из 12 возможных маршрутов включены 6.
- Банк калиброван моделью Раша на общей шкале theta; новые задания встраиваются среди уже откалиброванных. Весь банк перекалибровывался вместе со вторым исследованием standard setting (июль 2014).
- Границы уровней CEFR на шкале theta задавала панель из 15 экспертов.
- Целевая стандартная ошибка измерения: не более 0,45 для 50-минутного теста и 0,29 для 120-минутного.
- Корреляция с TOEFL iBT (выборка 384) и с IELTS (выборка 406): авторы пишут о заметных положительных связях и оговаривают малый размер выборки.
- Документы защищены авторским правом EF Education First Ltd.

Вывод: сама схема ca-MST + Rasch — стандартная публичная методика, не принадлежит EF. Мы реализуем её со своими заданиями, своей калибровкой и своими границами. Модули, пороги, параметры и числа EF не переносятся.

Чего нет: числа вопросов в модулях (в отчёте «tasks», каждое содержит несколько вопросов), точных порогов маршрутизации, параметров заданий.

## Языки

- Два языка (ru, en) только у посадочной, FAQ, юридических страниц и писем. Выбор языка хранится в `profiles.locale`, по умолчанию по языку браузера.
- Внутри теста, на странице результата и в сертификате только английский. Плюс: нет перевода инструкций и нет риска подсказки через перевод; минус: слабый новичок (A1) может не понять инструкции. Меры: инструкции на уровне A1 лексики (из CEFR-J), примеры до старта, на странице перед стартом краткая памятка на русском.
- Библиотека i18n нужна только для маркетинговых страниц (Next.js роутинг `/ru`, `/en`).

## Schema

16 таблиц, см. `replica/schema.sql`. Применена на Postgres 16 и проверена: схема загружается без ошибок.
Права: RLS включён на всех таблицах. На банке заданий и калибровке политик нет, поэтому клиент их не читает. Запись и вся тестовая логика идут через серверные маршруты с ключом service role.

Ограничения, проверенные на живой базе:
- не более одной незавершённой сессии на пользователя (частичный unique index);
- одна диагностическая попытка в 90 дней (триггер);
- повторный ответ на то же задание отклоняется (unique `session_id, item_id`);
- задание на аудирование без аудиофайла не создаётся (check);
- каждое задание обязано иметь источник с лицензией. Поле `commercial_use_ok` фильтрует банк: задания из источников без права коммерческого использования не попадают в боевой тест.

Известное ограничение: триггер лимита 90 дней проверяет данные в момент вставки. Два параллельных запроса одного пользователя закрыты уникальным индексом открытой сессии. Если позже появятся сессии разных видов, правило надо пересмотреть.

Webhooks in: нет на старте (платежей нет).
Jobs: `expire-sessions` каждые 5 минут (сессии с просроченным `deadline_at` → `expired`); `purge-events` раз в сутки (удалять `session_events` старше 90 дней).

## Калибровка без методиста

1. Написать банк с запасом: минимум в 3 раза больше заданий, чем нужно в панели (на панель из 8 модулей с 6 заданиями это около 150 заданий на навык).
2. Пилот: 200–300 человек, заходящих с разными уровнями, формы с общими «якорными» заданиями для связи шкал. Сбор через анонимные ссылки.
3. Калибровка Rasch (Python, вручную): `item_difficulty`, отчёт по заданиям (infit, доля верных, дискриминация), удаление плохих.
4. Границы уровней: до внешнего эксперта брать предварительные по тегам CEFR-J и по внешней сверке (участники приносят результат признанного теста: IELTS, TOEFL, Cambridge, Duolingo). Отметка «предварительно» в интерфейсе.
5. Повторять после накопления данных: каждые 500 новых сессий — перекалибровка, версия в `calibrations`.

Это не заменяет методиста. Цена ошибки: границы уровней будут смещены. Допустимо для личной диагностики, недопустимо как «сертификат» для работодателей.

## The parts that bite

- **Содержание теста.** Главная стоимость и риск. Код проще, чем 300 хороших заданий и пилот.
- **Утечка заданий.** Нет прокторинга; рассчитывать, что банк будет собран из скриншотов. Нужны разные формы, ротация заданий, лимит попыток.
- **Таймер.** Дедлайн хранится на сервере (`deadline_at`), клиентский таймер только отображение.
- **Обрыв связи.** EF отменяет сессию без возобновления. Мы можем сделать лучше: продолжать с текущего модуля в пределах дедлайна, раз модуль целиком отдаётся и ответы пишутся по одному. Решение продуктовое.
- **Идемпотентность.** Двойная отправка ответа: unique-ключ в базе; сервер возвращает прежний ответ.
- **Аудио в Safari.** Автовоспроизведение блокируется без жеста пользователя. Нужна кнопка запуска.
- **Время и часовые пояса.** Всё в UTC, показ по локали браузера.
- **Минимальный возраст.** 16 лет, иначе нужно согласие родителя; для 13–15 лет у EF отдельное правило. Отложить до юридической консультации.
- **Персональные данные.** Нужна политика конфиденциальности, удаление по запросу, при пользователях из ЕС GDPR.
- **Публичная ссылка.** Токен 128 бит, отключение по флагу `is_public`, никаких идентификаторов пользователя в URL.
- **Честность формулировок.** Не называть «CEFR-сертификатом» и не ссылаться на EF, TOEFL, IELTS как на эквиваленты без собственных данных.

## Build order

1. **Вертикальный срез.** Регистрация → один модуль из 5 заданий чтения → подсчёт балла → страница результата. Экраны S01, S08, S10, S13. Таблицы profiles, items, test_sessions, responses, results. Маршруты: POST /sessions, GET /next, POST /answers, POST /finish. Цель: доказать стек и конвейер, без адаптивности и без калибровки (фиксированная форма).
2. **Must-haves.** Адаптивная панель из трёх стадий (S10, S11), аудиоплеер (S11), оценка theta, страница результата (S13), публичная ссылка (S14), регистрация и согласие (S08). Таблицы panels, modules, module_items, routing_rules, calibrations, item_difficulty, cut_scores, certificates.
3. **Пилот.** Заполнение банка, анонимный сбор, калибровка, первые границы уровней.
4. **Should-haves.** PDF результата (S15), практический тест на 20 вопросов (S16), лимит 90 дней, обновление результата при пересдаче, посадочная ru/en (тест только на английском), ограничение по возрасту.
5. **Could-haves.** LinkedIn, поиск результата по данным, корпоративные ссылки, письмо и речь.
6. **Fixes** из `/replica-entrepreneur`, когда он отработает.
