Найдены прогоном /replica-test

B-001 · S4 · Нет favicon: 404 в консоли на каждой странице

  • Шаги: открыть любую страницу в Chromium с отслеживанием консоли.
  • Ожидали: консоль без ошибок. Получили: Failed to load resource: 404 (запрос /favicon.ico).
  • Доказательство: 14 из 31 тестов падали на проверке консоли (фикстура guard).
  • Исправление: добавлен src/app/icon.svg. Проверка: все UI-спецификации проходят без ошибок консоли.

B-002 · S3 · Параллельная отправка части 1 даёт несколько успешных ответов с разными наборами текстов

  • Шаги: три одновременных POST /api/vocab с одним токеном (повтор запроса после потери ответа даёт то же самое).
  • Ожидали: один 200, остальные 409. Получили: три 200; каждый клиент получил свой набор из 10 текстов, в базе остался последний. Ответы на тексты «чужого» набора отклонялись бы как неизвестные вопросы.
  • Доказательство: F01-E10 (падал: 3 вместо 1).
  • Исправление: атомарный переход статуса update … where status='vocab', остальные получают 409. В reading добавлена блокировка строки сессии (FOR SHARE), в finish обновление условное, чтобы ответы не записывались после завершения и результат не перезаписывался. Для двух последних гонок отдельного падающего теста нет (не воспроизводил), это упреждающее ужесточение.

B-003 · S3 · Ограничение частоты обходится подделкой заголовка

  • Шаги: 31 запрос POST /api/start с X-Forwarded-For: <разные левые адреса>, <один реальный>.
  • Ожидали: 429 на 31-м. Получили: все 200. Ключом служил левый элемент, его задаёт клиент.
  • Доказательство: F01-N8b (падал).
  • Исправление: ключ — последний элемент (его дописывает прокси платформы). Оговорка: без прокси перед приложением заголовок подделывается целиком, там ограничение не защищает.

Проверить (не воспроизведено или не автоматизируется)

  • Реальный iOS Safari и Android Chrome: клик по скрытому радио через метку, автозаполнение, «beforeunload».
  • Экранные дикторы (VoiceOver, TalkBack, NVDA): автоматический axe прошёл на всех экранах без нарушений, но ручной прогон не делался.
  • Двойной клик на медленных устройствах: тест проходит, потому что оба обработчика видят одно состояние; на очень медленном рендере возможен пропуск слова. Если в пилоте будет много коротких ответов по ~100 мс, проверить по time_ms.
  • Работа за настоящим прокси хостинга: какой заголовок и сколько прокси (см. B-003).
  • Cookie pid ставится с secure только в production, проверить на HTTPS-стенде.
  • Потеря прогресса при закрытии вкладки заложена в дизайн, но может раздражать: смотреть долю незавершённых сессий в пилоте.
  • Юридические тексты не проверены юристом.

Дополнение: аудирование (часть 3)

Прогон 7 тестов F03 и сканирования axe экрана аудирования новых дефектов не нашёл. Тесты на звук идут с WAV-заглушками (scripts/make-test-audio.mjs), то есть проверяются маршрут, права, Range, лимит прослушиваний в интерфейсе и запись ответов, но не качество реального аудио. Проверить вручную: воспроизведение в Safari iOS (жест пользователя, Range), Android Chrome, наушники, поведение при медленном соединении (буферизация), повторное нажатие Play во время загрузки. Лимит прослушиваний сейчас ограничивается на клиенте; сервер отдаёт файл при любом числе запросов. Для пилота это допустимо, но участник, знающий об этом, может переслушать запись. Если пилот покажет подозрительные паттерны, добавить серверный счётчик.
